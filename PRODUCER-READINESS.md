# Готовность производителей телеметрии Windows

Приёмка: 21.10.2026. Область — публикация готовых данных виджетов ресурсов и подписочных квот. Исходники приняты в локальном коммите до публикации; хэш публикации в репозитории иной. Код производителей установлен в существующие рабочие каталоги и проверен в живой работе. Интеллектуальная оркестрация S.I.G.M.A. и реализация/приёмка Bridge, CLI и MCP в этот пакет не входят.

Машиночитаемое доказательство: receipt (сырые замеры хранятся вне публичного репозитория). Служебные журналы, резервные копии, копии живых снимков и готовые локальные архивы хранятся вне публичного репозитория.

## Версии и релизы

Опубликованный релиз Ресурсов 1.1.1 (v0.1.1) не содержит публикатора телеметрии; исходники на main опережают этот релиз, а версия 1.1.1 в них пока не повышена. До публикации следующего релиза Ресурсов версию нужно повысить отдельным пакетом (Program.cs, app.manifest, START-HERE, имена архивов в скриптах сборки и проверки релиза), иначе сборка с публикатором будет неотличима от v0.1.1. Лимиты: 1.1.0 в v0.2.0.

## Причина задержки и исправление

Фазовый профиль старого C# writer локализовал задержку в `File.Replace`: p95 этой фазы 19,826 ms при p95 всей фоновой операции 23,1783 ms; sharing retries отсутствовали. Проверки ACL и путей занимали доли миллисекунды. Исходное измерение (сырые замеры хранятся вне публичного репозитория) сохранено.

Публикация теперь переименовывает эксклюзивно открытый временный файл через документированный `SetFileInformationByHandle`: `FileRenameInfoEx` с заменой существующего имени и POSIX-семантикой, `RootDirectory = NULL`, полный проверенный путь цели. Копирования между томами нет. Для неподдерживаемого класса предусмотрен ограниченный классический fallback. Совместимый открытый reader сохраняет старый полный JSON, новое открытие видит новый полный JSON. Temp остаётся открытым до завершения замены и удаляется при отказе по собственному handle. Предварительного удаления target нет.

Приватность каталога, owner/ACL, reparse/alias guards, global mutex, удерживаемый lock, latest-value slot и ограничение 1 MiB сохранены. Целевой DACL переносится без расширения; любое несовпадение фактически применённого DACL с требуемым вызывает отказ до переименования. Исправлены накопление temp при отказе ACL и ошибочная постоянная остановка после sharing failure первой публикации. Проверки безопасности не отключались, приоритет потока и разрешение системного таймера не повышались, антивирус не менялся.

Writer в репозитории позднее дополнен (PR #1, `CreateOwned`: явный владелец-SID для создаваемых temp и lock); хэш и измерения ниже относятся к версии на 21.10.2026. SHA-256 измеренного production writer: `6b4ecaaa66a376414856394913632beaa69be75da28b1b2cb644a92a6310adce`.

Оба исходных бюджета выполнены: p95 ≤10 ms и среднее CPU ≤5 ms. Первый результат (сырые замеры хранятся вне публичного репозитория), второй результат. Измеряется весь worker, включая сериализацию, UTF-8, проверки, ввод-вывод, перенос ACL, rename и закрытие handle. Инструментирована отдельная копия настоящего исходника; используются синтетические неизменяемые данные, интервал 1 s и monotonic Stopwatch. Исходные операции не удаляются и не переставляются, накладные расходы не вычитаются. Manifest каждого прогона хранит хэши. CPU относится ко всему harness и квантован Windows. Это контрольные прогоны на данной машине, не абсолютная гарантия задержки на любом ПК и не отдельный замер установленного GUI.

## Граница API и следующего пакета

API-виджет развивается другим исполнителем. Его UI/credentials не изменялись. Готового версионированного producer-export нет; внутренний UI state и headless dump не являются согласованным фоновым контрактом.

Во время приёмки смежный пакет подготовил черновик расширения (в публичный репозиторий не включён): `api-balances-snapshot.json`, `schemaVersion 1.1.0-draft`; время `measured_at`/`published_at`/`last_attempt_at`, статусы, `pools[]`, `connections[]`, `entries[]`; непрозрачные `provider_id`, `account_id`, `connection_id`, `shared_pool_id`. Один общий баланс нескольких ключей нельзя суммировать повторно; денежные данные API отделены от подписочных окон. Producer, активация reader и соглашение с потребителями ещё требуются. Этот черновик не заменяет действующий контракт 1.0.0: `api_limits` остаётся `not_available / monitor_not_implemented`.

Работа над Bridge/CLI/MCP и черновыми extensions выполняется отдельным пакетом; её файлы, публичная страница, README и изменения API-виджета не включены в коммит производителей. Готовность того пакета здесь не утверждается.
