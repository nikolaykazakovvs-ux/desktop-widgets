# AI Telemetry Bridge: приёмка этапа 1

19 октября 2026 года, Windows x64. Этап 1 выполнен локально: подготовлены контракт, синтетические примеры, проверочный эталон, транспортный прототип и проверка совместимости. Это не установленный производственный Bridge и не подтверждение его использования ведущим в обычной работе.

## Результаты

| Критерий этапа | Подтверждение |

Основные материалы: [контракт](ai-telemetry-contract.md), [совместимость и доказательства](ai-telemetry-compatibility.md), прототип и воспроизведение, [утверждённый план](ai-telemetry-bridge-plan.md).

Область этой приёмки — документы AI Telemetry и каталог `telemetry/`. При окончательной проверке checkout обнаружены параллельные изменения README, публичной страницы, `.gitignore` и материалов API-виджета. Они не относятся к этому этапу, не изменялись исполнителями этапа и не включены в его вердикт. Общий commit или публикация не выполнялись.

## Измерения и решения

Финальный короткий запуск выполнен 18 октября в 23:04:51 UTC / 19 октября в 02:04:51 по Киеву на занятом рабочем ПК. Компактный ответ — 7515 bytes; форматированный файл — 12409 bytes. Выполнялся один клиент, операции последовательно: 50 тёплых чтений/вызовов, 10 холодных запусков, 50 синтетических публикаций. p95 при десяти холодных запусках является грубой оценкой, совпадающей с максимумом выборки.

| Операция | p50 | p95 | Начальный ориентир на этом ПК |
|---|---:|---:|---|
| Чтение JSON без валидации | 0,64 мс | 1,05 мс | Исследовательская цель около 1 мс; не гарантия |
| Чтение со структурной валидацией | 1,07 мс | 1,84 мс | p95 ≤ 2 мс |
| Запрос к работающему MCP | 2,55 мс | 3,43 мс | p95 ≤ 10 мс |
| Холодный CLI с загрузкой и проверкой схемы | 728,03 мс | 902,07 мс | p95 ≤ 1500 мс |
| Синтетическая запись, fsync и замена | 4,81 мс | 6,77 мс | p95 ≤ 10 мс |

Рабочий набор памяти MCP-процесса в конце измерения — 112,54 МиБ, ориентир — не более 128 МиБ для одного экземпляра. Это выборочное RSS, не непрерывно измеренный пик. CPU сервера за 50 вызовов — 125 мс; CPU синтетических публикаций — 109 мс за 50 операций, в среднем 2,18 мс на операцию при ориентире ≤ 5 мс. Эти значения не являются процентом общей нагрузки машины.

Для прототипа принят установленный Node.js и официальный MCP SDK с закреплёнными зависимостями. Постоянное stdio-подключение к ведущему предпочтительно для повторных запросов: холодный запуск существенно дороже чтения. Стоимость отдельного процесса учитывается явно; автоматическое подключение отдельного сервера каждому исполнителю не предусматривается. Согласованная в этом запуске версия протокола — `2025-11-25`; номер установленного SDK сам по себе не доказывает другую версию согласования.

Публикационный бюджет имеет запас относительно измерения, но относится только к синтетической записи Node. Настоящий C# writer, сериализация виджетов, конкурентные читатели, ACL и последствия ошибок замены ещё должны проверяться в своих этапах. Пороги давления на ресурсы — диагностические начальные правила, а не гарантия безопасного запуска задачи. Никаких автоматических решений о числе агентов или распределении квот не добавлено.

## Организация и границы проверки

Перед назначением прочитан готовый кэш лимитов отдельно по каждому провайдеру. На начале этапа у Codex оставалось 39% недельного окна; Claude/Antigravity и короткое окно Kimi были исчерпаны. Последующие назначения также сверялись с обновлённым кэшем. Эти датированные значения не являются текущими лимитами и не используются как постоянная политика.

Однократный штатный аппаратный снимок перед распределением работы показал CPU 69%, свободную RAM около 10,4 ГиБ, commit headroom около 35,3 ГиБ. Назначены два независимых автора и затем независимый ревьюер — GPT-6.1 Sol с high effort в настройках назначения; Root выполнил интеграционную приёмку и последовательные локальные проверки. Изменение общей квоты аккаунта не приписывается этой задаче: другие сессии используют тот же пул.

Ревью выявило невозможный положительный запас commit при неизвестном исходном операнде и отсутствие безопасного верхнего предела длительности подписочного окна. Оба контрпримера теперь отклоняются. Дополнительно проверены отдельная свежесть RTT и сетевых счётчиков, тип GPU-памяти и отсутствие ложного нулевого loss без проб.

В тесте Codex подтверждены завершение собственного app-server и отсутствие исходного процесса fixture по его точной нативной идентичности. Удаление временного профиля встретило Windows `EBUSY`; диагностический каталог сохранён в игнорируемом Git локальном рабочем каталоге. Это не скрывается как успешное удаление. Первые неудачные попытки очистки сохранены отдельно. Финальное разделение функционального успеха и предупреждения об очистке в сценарии внесено после этого запуска; повторный нативный запуск только ради смены классификации не выполнялся. Рабочие профили и настройки клиентов не менялись.

Проверка Antigravity ограничена доступными командами справки; его фактический обмен MCP не подтверждён. Текущий открытый desktop-чат не получил новый инструмент. Запросы моделей, автоматическое использование данных ведущим, поставка пользователю и реальный пилот не входят в достигнутый результат этапа 1.

## Следующая граница работы

Этапы 2 и 3 могут использовать этот контракт для независимых производителей. При этом сетевой адаптер обязан передавать исходные времена существующих проб и корректные UTC-границы местного дня, включая переходы часового пояса; нельзя подставлять время нового снимка вместо времени старого измерения. Настройки рабочего ведущего, общий процесс оркестрации, публикация и релиз остаются отдельными этапами принятого плана.
