## Историческая приёмка 19.10.2026

19 октября 2026 года. Публикаторы обоих виджетов реализованы и функционально проверены локально. Этап 3 прошёл предусмотренные проверки данных и heartbeat. У этапа 2 остаётся незакрытым первоначальный исследовательский ориентир накладных расходов: фоновая запись не уложилась в p95 ≤10 ms. Полная приёмка этого критерия не заявляется.

Это исходники и проверенные локальные сборки. Установленные соседние копии виджетов не обновлялись, рабочие клиенты к мосту не подключались, commit/push и новый релиз не выполнялись. Параллельные изменения README, публичной страницы и API-виджета не входят в эту приёмку.

## Реализация

- Виджет ресурсов передаёт уже собранный Sample в отдельный publisher после Collect и перед Updated. Неизменяемая проекция, один ожидающий снимок, фоновая сериализация/запись и предел 1 Hz сохраняются при скрытой карточке. Нового сборщика ОС или сетевого ping нет.
- Температуры, GPU memory kind, RAM/commit и сеть сохраняют исходные времена. Неизвестное не превращается в ноль. Поздний результат сетевой пробы предыдущего дня больше не увеличивает счётчики нового дня; RTT сохраняет своё время.
- Виджет подписок публикует завершения отдельных провайдеров, не ожидая медленного соседа. Heartbeat 10 секунд не вызывает Collect и не обновляет measured_at. Устойчивые IDs и исходные доли квот сохраняются до оформления UI; визуальный reset не восстанавливает квоту в экспорте.
- Общий writer обеспечивает одного писателя на файл через mutex и удерживаемый файловый lock, приватные ACL, проверки reparse/коротких имён, ограниченные sharing retries и замену полностью закрытого временного файла. Ошибка публикации не останавливает интерфейс или сбор.
- Read-only режимы dump/render не публикуют рабочую телеметрию. Тестовые источники не переходят к настоящим аккаунтам при отсутствии фикстуры.

Описание: [ресурсы](ai-telemetry-resources-publisher.md), [подписочные квоты](ai-telemetry-quotas-publisher.md), [контракт](ai-telemetry-contract.md).

## Независимое ревью и исправления

Внешний Kimi Code получил read-only пакет после зелёных профильных проверок. Выбраны alias `kimi-code/k3` и effort high; фактический backend model ID отдельно не раскрывался runtime. Исходный отчёт (сырые замеры хранятся вне публичного репозитория) выявил два P2: unknown reachability со scope gateway и обход fixture/live guard через DOS alias. Исправления выполнены отдельным пакетом, затем проверены Root кодом и прогонами выше. P1 не найдено.

При интеграционной проверке Root сохранил target ACL/reparse проверку непосредственно перед каждой заменой, убрав её дублирующий вызов перед созданием приватного temp. ACL временного файла проверяется через удерживаемый эксклюзивный FileStream до закрытия; API возвращает права именно файла открытого потока ([Microsoft](https://learn.microsoft.com/en-us/dotnet/api/system.io.filestream.getaccesscontrol?view=netframework-4.8.1)). Защитная политика не ослаблялась; затронутые проверки повторены.

## Накладные расходы: ориентир пока не принят

Первый измеритель смешивал стоимость писателя с Thread.Sleep-поллингом и дорогими процессными измерениями. Его исходный результат (сырые замеры хранятся вне публичного репозитория) сохранён, но не используется для утверждения о собственной задержке writer.

Уточнённый измеритель компилирует отдельную копию реального writer с добавленными Stopwatch/event отметками. Уникальные места вставки проверяются; исходные операции не удаляются и не переставляются. Manifest (сырые замеры хранятся вне публичного репозитория) сохраняет SHA-256 исходника и инструментированной копии. Поллинг и RSS измерения исключены из интервалов worker/CPU; глобальное разрешение таймера Windows не меняется.

Два прогона финального production writer выполнены по 30 публикаций с интервалом 1 секунда, из них 29 steady. Его SHA-256 совпадает с manifest и измерением: `e168b57cfe12eb5e5a9db6c85a586873165a8fc8e3a8cdd14de01ad3f933c0a9`.

| Метрика | Первый прогон 30 | Диагностический прогон 30 |
|---|---:|---:|
| Capture + Submit на стороне сборщика, p95 | 0,127 ms | 0,180 ms |
| Фоновая операция writer, p95 | 21,809 ms | 24,068 ms |
| Средний CPU всего тестового процесса на steady-публикацию | 5,388 ms | 2,694 ms |
| Sharing retries | Не выделялись отдельно | 0 |

Неизменённые результаты: первый прогон (сырые замеры хранятся вне публичного репозитория), прогон с учётом retries. Нулевой счётчик retries исключает ожидание повторной попытки в последнем опыте; точный вклад каждой операции ACL/файловой системы отдельно не измерен. Исторический короткий native-прогон до оптимизации также сохранён.

Ориентиры этапа 1 — p95 ≤10 ms и CPU ≤5 ms/операцию — были получены на synthetic Node-прототипе без полного набора проверок настоящего C# writer. На текущей Windows фоновой latency-ориентир не выполнен; CPU показал вариабельность около границы. Они не расширялись автоматически ради PASS. Передача из сборщика остаётся короткой и не ждёт диска. Последнее sampled RSS тестового процесса — около 26,04 MiB; это весь harness с загруженными классами, не дополнительная память установленного виджета и не пик.

Все времена относятся к synthetic данным и этой занятой машине. Это не гарантированные пределы для других ПК и не отдельное измерение quota heartbeat. Полная приёмка производительности этапа 2 остаётся открытой; функциональные и защитные проверки от этого не объявляются непроведёнными.

Контрольный эксперимент со штатным приоритетом потока (сырые замеры хранятся вне публичного репозитория) не подтвердил улучшения: p95 фоновой операции 38,27 ms при нуле retries. Пониженный приоритет восстановлен; SHA-256 production writer снова точно совпадает с двумя основными прогонами выше. Это наблюдение на занятом host, а не доказательство причинного влияния приоритета. Ослабление проверок безопасности, повышение глобального разрешения таймера и увеличение частоты публикации не использовались.

## Границы достоверности источников

Claude get_usage и текстовый /usage могут возвращать кэш без времени и признака его происхождения. Поэтому эти пути не создают ложное свежее измерение. Timestamped desktop history и typed state-cache сохраняют исходное время. UI-полосы сохранены. Для Kimi прямой путь подтверждён чтением кода установленного источника, для остальных поддерживаемых путей — указанными в документе квот первичными источниками. Проверки публикаторов не опрашивали реальные квоты.

## Выполнение и трения

Назначения проверялись по готовому кэшу лимитов. Начальная нагрузка: CPU 25,2%, свободная RAM 10,12 GiB, commit headroom 36,3 GiB. При исчерпанных внешних пулах работали два внутренних автора. После подтверждённого восстановления Kimi независимое ревью, исправления и уточнение измерителя переданы ему. Сборки и локальные прогоны выполнялись последовательно.
