# Границы AI Telemetry Bridge и S.I.G.M.A.

Решение оператора от 21.10.2026 (Europe/Kyiv). Проектов два: Desktop Widgets и S.I.G.M.A. Отдельный третий проект «умный коннектор» сейчас не создаётся. Этот документ фиксирует ответственность; он не подтверждает готовность или установку интеграции.

## Ответственность проектов

| Область | Ответственный проект | Что входит |
|---|---|---|
| Сборщики ресурсов ПК, лимитов подписок и API-балансов | Desktop Widgets | Сбор и публикация показателей по фактической готовности источников; единые данные для интерфейса, Bridge и потребителей |
| Интерфейс виджетов | Desktop Widgets | Отображение данных, истории и предупреждений человеку |
| AI Telemetry Bridge | Отдельный модуль Desktop Widgets в `telemetry/` | Чтение опубликованных снимков, проверка контракта, свежести и качества, детерминированные признаки, выдача фактов через MCP (Model Context Protocol) и CLI (командный интерфейс) |
| Интеллектуальная оркестрация | S.I.G.M.A. | Понимание задач и политики, выбор моделей и исполнителей, надзор и управление выполнением; полномочия передаются по мере приёмки функций |

## Правила для следующих агентов

- Не создавать в `sigma-core` копии сборщиков ресурсов, квот и API-балансов Desktop Widgets. Если не хватает показателя, расширять соответствующий сборщик и контракт в Desktop Widgets; в S.I.G.M.A. добавлять только потребляющий адаптер.
- Bridge не опрашивает источники повторно при запросе и не выбирает исполнителей. Он не получает планировщик или очереди заданий, автономную маршрутизацию, управление агентами и модельные рассуждения. Детерминированные `orchestration_hints` сохраняются и не являются интеллектуальной оркестрацией.
- Наблюдение за заданиями и процессами исполнителей остаётся собственной функцией S.I.G.M.A. Запрет дублирования относится к ресурсной, квотной и API-телеметрии Desktop Widgets, а не ко всем инструментам наблюдения.
- Прямое чтение готовых снимков в S.I.G.M.A. — интеграционный адаптер. Переход на проверенный контракт Bridge выполняется после его приёмки; это решение не требует немедленно менять работающий код.
- Контракт данных принадлежит Desktop Widgets и остаётся версионируемым. Изменения интерфейса согласуются с потребителями, включая S.I.G.M.A.; выбор моделей, исполнителей и управление заданиями в контракт данных не входят.
- Общая политика оркестрации остаётся в LLM-Orchestrator. Решение о границах не означает уже выполненную передачу управления от ведущего агента S.I.G.M.A.

## Уточнение 07.11.2026

Решение оператора: виджет «Балансы API» — отдельный проект. Его публикатор пишет `api-balances-snapshot.json` по расширению `api_limits` v1.1 ([описание](ai-telemetry-api-balances-extension.md)); контракт расширения и чтение (reader) остаются в Desktop Widgets, в `telemetry/`. Правило «не создавать в `sigma-core` копии сборщиков» не меняется: балансы API собирает один сборщик, и это сборщик проекта «Балансы API». Строка таблицы «Сборщики ресурсов ПК, лимитов подписок и API-балансов» читается с этим уточнением: сборщик балансов API находится в проекте «Балансы API». Таблица и правила решения 21.10.2026 выше не изменены; единственная правка шапки — обезличена атрибуция («оператора» вместо имени).

## Независимость от интерфейса и дальнейшее выделение

Зависимости телеметрии и отображения должны быть разделены. Отдельная поставка или режим без интерфейса допустимы после реализации и приёмки; наличие модуля само по себе их не подтверждает.

Вынесение Bridge в отдельный репозиторий возможно позже при самостоятельном продукте и цикле релизов, по отдельному решению. Сейчас модуль развивается в Desktop Widgets.

Согласованная запись в смежном проекте: [архитектура S.I.G.M.A.](../../../sigma-core/docs/sigma-architecture.md#решение-о-границах-bridge-и-sigma-21102026). Это межпроектная ссылка для локального workspace; в отдельном клоне Desktop Widgets соседний проект может отсутствовать.
