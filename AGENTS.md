# AGENTS.md — правила работы в Desktop Widgets

Проект Desktop Widgets: C#/WPF-виджеты под `windows/` и AI Telemetry Bridge в `telemetry/`. Общие правила оркестрации и политика предоставляются средой исполнения агента; здесь они не копируются. Ниже — только специфика проекта.

## Перед работой

Перед выбором инструментов проверить их реальные возможности и существенные ограничения по действующей документации и среде исполнения.

1. Определить корень и состояние Git: ветка, `git status`, чужие незавершённые изменения. Их сохранять, не откатывать, не перезаписывать, не переносить и не коммитить без поручения.
2. Прочитать [решение о границах Bridge и S.I.G.M.A.](docs/bridge-sigma-boundaries.md). Перед изменением реализации дополнительно читать действующие план и контракт Bridge в `docs/`, проверяя их фактическое наличие и статус в рабочем дереве.

## Структура

| Каталог | Назначение |
|---|---|
| `windows/` | Сборщики данных (ресурсы ПК, лимиты подписок, API-монитор по фактической готовности) и UI виджетов |
| `telemetry/` | Bridge, схемы (`telemetry/schema/`), проверки (`telemetry/tests/`), фикстуры |
| `docs/` | План, контракт, результаты приёмки, совместимость |

## Границы Bridge и S.I.G.M.A. (решение 21.10.2026)

- Проекта два: Desktop Widgets и S.I.G.M.A.; отдельный проект «умный коннектор» не создаётся.
- Сборщик в `windows/` — единственный источник данных для UI, Bridge и потребителей. Копии сборщиков в других проектах не заводить; недостающий показатель добавлять в сборщик и контракт здесь.
- Bridge — отдельный модуль Desktop Widgets: читает опубликованные снимки, проверяет контракт, свежесть и качество, считает детерминированные признаки и выдаёт факты через MCP (Model Context Protocol) и CLI (командный интерфейс). Он не опрашивает источники при запросе, не выбирает исполнителей и не получает scheduler, очереди заданий, routing, управление агентами и модельные рассуждения. Интеллектуальная оркестрация — область S.I.G.M.A.
- Архитектурная независимость Bridge от UI — требование развития: зависимости телеметрии и отображения разделять. Наличие модуля не подтверждает готовность отдельной поставки, режима без UI или установщика; их состояние проверять по реализации и приёмке.
- Контракт версионируется; изменения интерфейса согласовывать с потребителями. Вынесение Bridge в отдельный репозиторий — только по отдельному решению.

## Дисциплина

- Один writer на область. Статусы «написано», «проверено», «принято» различать и фиксировать только подтверждённое.
- Секреты в код, документы и журналы не попадают.
